# java-lotto-precourse
## 🚀 **미션 개요**

**로또 발매기 프로그램**을 구현한다.

사용자가 입력한 금액만큼 로또를 구매하고,

당첨 번호 및 보너스 번호를 입력받아 **당첨 결과와 수익률을 계산**한다.

이번 미션의 목표는 **객체 지향 설계와 단위 테스트**를 통해 안정적이고 유지보수 가능한 코드를 작성하는 것이다.

## 🧩 기능 요구사항

### 1. 로또 구매 및 발행 기능

- [ ]  구입 금액을 입력받는다.
    - [ ]  금액이 1,000원 단위가 아니면 예외 발생
        
        → `[ERROR] 구입 금액은 1,000원 단위여야 합니다.`
        
    - [ ]  금액이 숫자가 아닐 경우 예외 발생
        
        → `[ERROR] 잘못된 입력입니다. 숫자를 입력해 주세요.`
        
- [ ]  구입 금액에 따라 구매 가능한 로또 개수를 계산한다.
    
    (예: 8,000원 입력 시 8개 발행)
    
- [ ]  랜덤으로 **중복되지 않은 6개의 숫자(1~45)** 를 뽑는다.
    - [ ]  중복 숫자가 존재할 경우 예외 발생
        
        → `[ERROR] 로또 번호는 중복될 수 없습니다.`
        
- [ ]  생성된 로또 번호를 오름차순으로 정렬하여 출력한다.

### 2. 당첨 번호 입력 및 검증 기능

- [ ]  당첨 번호 6개를 입력받는다. (쉼표 구분)
    - [ ]  숫자가 아닌 값이 포함된 경우 예외 발생
        
        → `[ERROR] 숫자만 입력할 수 있습니다.`
        
    - [ ]  중복된 번호가 있을 경우 예외 발생
        
        → `[ERROR] 당첨 번호는 중복될 수 없습니다.`
        
    - [ ]  1~45 범위를 벗어나는 경우 예외 발생
        
        → `[ERROR] 로또 번호는 1부터 45 사이의 숫자여야 합니다.`
        
    - [ ]  6개의 번호가 아닌 경우 예외 발생
        
        → `[ERROR] 당첨 번호는 6개여야 합니다.`
        
- [ ]  보너스 번호를 입력받는다.
    - [ ]  숫자가 아닌 경우 예외 발생
    - [ ]  1~45 범위 밖의 숫자면 예외 발생
    - [ ]  당첨 번호와 중복될 경우 예외 발생
        
        → `[ERROR] 보너스 번호는 당첨 번호와 중복될 수 없습니다.`
        

### 3. 당첨 결과 계산 기능

- [ ]  사용자가 구매한 모든 로또를 순회하며 당첨 번호와 비교한다.
- [ ]  일치한 숫자 개수와 보너스 번호 일치 여부를 판단한다.
- [ ]  일치 결과에 따라 `Rank`(Enum)으로 등수를 구분한다.
    - [ ]  6개 일치 → 1등 (2,000,000,000원)
    - [ ]  5개 + 보너스 번호 일치 → 2등 (30,000,000원)
    - [ ]  5개 일치 → 3등 (1,500,000원)
    - [ ]  4개 일치 → 4등 (50,000원)
    - [ ]  3개 일치 → 5등 (5,000원)
    - [ ]  그 외는 미당첨
- [ ]  당첨 내역을 출력 형식에 맞게 출력한다.

### 4. 수익률 계산 기능

- [ ]  모든 당첨 금액의 총합을 계산한다.
- [ ]  수익률을 구입 금액 대비 퍼센트(%)로 계산한다.
    - [ ]  소수점 둘째 자리에서 반올림한다.
- [ ]  “총 수익률은 X%입니다.” 형식으로 출력한다.

### 5. 예외 처리 및 프로그램 흐름 제어

- [ ]  예외 발생 시 `IllegalArgumentException`으로 처리하고,
    
    에러 메시지를 `[ERROR]`로 시작하도록 출력한다.
    
- [ ]  예외 발생 시 해당 입력 단계부터 다시 입력받는다.
- [ ]  프로그램 종료 시 `System.exit()`를 호출하지 않는다.

### 6. 구조 및 테스트 관련

- [ ]  **Enum**을 활용하여 등수와 상금 관리
- [ ]  **상수(static final)** 로 하드코딩 방지
- [ ]  **단위 테스트 작성**
    - [ ]  `Lotto` 생성 유효성 검증 테스트
    - [ ]  `Rank` 계산 테스트
    - [ ]  `LottoResult` 수익률 계산 테스트
    - [ ]  `WinningLotto` 비교 로직 테스트
- [ ]  UI(`System.out`, `Console`) 관련 테스트는 제외한다.

### 코딩 컨벤션 및 리팩토링 원칙

- **`Lotto`** 클래스 외부에서 **`numbers`**를 직접 변경할 수 없도록 불변성 유지
- 입력값 검증 로직은 별도 유틸 또는 Validator로 분리
- 메서드는 15라인 이하로 작성
- 들여쓰기는 2단계 이내로 제한
- **`else`**, **`switch`**문 사용 금지 (조기 반환 return 사용)
- 필요 시 **`List`**, **`Map`** 등을 활용하여 결과를 효율적으로 집계
